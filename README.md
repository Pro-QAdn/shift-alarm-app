# ShiftAlarm Android App

Мобільний застосунок для Android для керування будильниками за складними змінними графіками: нічні та ранкові підйоми, вихідні, циклічні шаблони й разові винятки.

## Мета проєкту

Створити локальний будильник, який дає змогу налаштувати циклічний графік на майбутнє, швидко змінювати окремі дні та бачити, чи готовий наступний сигнал до спрацювання.

> **Обмеження платформи:** жоден сторонній застосунок не може гарантувати спрацювання за будь-яких умов. Android може обмежувати точні будильники, повноекранні сповіщення та роботу після примусової зупинки. Застосунок має перевіряти доступні дозволи й явно повідомляти про проблеми.

## Функціональні вимоги

### 1. Надійне планування будильників

- Планування точних локальних сигналів через Android AlarmManager з відповідним API для будильників.
- Власний механізм відтворення сигналу, незалежний від застосунку «Годинник».
- Керування вимкненням сигналу та відкладенням на заданий інтервал.
- Перевірка дозволів на точні будильники та, за потреби, повноекранні сповіщення.
- Відновлення запланованих сигналів після перезавантаження пристрою.
- Перерахунок розкладу після зміни системного часу або часового поясу.
- Відображення фактичного стану наступного сигналу та зрозумілі повідомлення про проблеми.

### 2. Головний екран і календар

- Головний екран показує час і дату наступного підйому, тип дня та стан будильника.
- Місячний календар із часом підйому в комірці дня.
- Візуальні позначення для нічної зміни, ранкової зміни, вихідного, ручного винятку та скасованого будильника.
- Ручне коригування часу для будь-якого дня.
- Після редагування застосунок має чітко розрізняти разовий виняток і зміну шаблону.
- Зміни мають відразу оновлювати системні сигнали без створення дублікатів.

### 3. Циклічні шаблони графіка

- Створення шаблонів довільної довжини з назвами та часом підйому для кожного дня циклу.
- Обов'язкова дата початку циклу — точка відліку для генерації графіка.
- Попередній перегляд на 30, 60 або 90 днів.
- Застосування шаблону до вибраного діапазону дат.
- Можливість копіювати шаблони й створювати окремі винятки для конкретних дат.
- Ручні винятки не повинні непомітно зсувати решту циклу.
- Час кожного сигналу прив'язується до конкретної календарної дати, включно з переходом через північ.

Приклад циклу: нічний підйом о 23:45 → вихідний → ранковий підйом о 06:00 → нічний підйом о 23:45.

### 4. Простий будильник

- Швидке створення одноразового будильника на вибраний час.
- Простий будильник працює незалежно від циклічного графіка.
- Можливість змінити час, вимкнути або видалити одноразовий сигнал.

### 5. Кнопка «Змінити сьогодні»

Швидкі дії з головного екрана:

- Змінити час сьогоднішнього підйому.
- Скасувати сьогоднішній сигнал.
- Додати позаплановий підйом.
- Повернути день до значень шаблону.

Скасований сигнал має бути явно позначений. Зміна одного дня не повинна змінювати наступні дні циклу, якщо користувач окремо не редагує сам шаблон.

### 6. Керування системними сигналами та історія

Дані слід логічно розділяти на три частини:

- **Розклад:** шаблони, згенеровані підйоми й ручні винятки.
- **Системні сигнали:** актуальні будильники, заплановані через Android.
- **Історія:** минулі спрацювання, скасування та зміни розкладу.

Вимоги:

- Скасування застарілих системних сигналів після редагування або спрацювання.
- Обмежене вікно майбутніх сигналів із регулярним оновленням.
- Захист від дублювання під час повторного планування.
- Збереження історії та розкладу в локальній базі даних.

### 7. Надійність і резервні механізми

- Основний механізм — локальний точний будильник.
- Додатковий локальний сигнал/сповіщення як резервний механізм, якщо це дозволяє конфігурація Android.
- Контроль дозволів, запланованих сигналів і стану резервного механізму.
- Інструкції для користувача щодо налаштувань енергозбереження виробників, якщо вони потрібні.
- Обробка перезавантаження, зміни часу й часового поясу.
- Чітке попередження, якщо точне планування недоступне або потрібні дозволи вимкнені.

Push-повідомлення не вважаються основним резервним будильником: їх доставка залежить від мережі та зовнішніх умов. Постійна фонова служба або watchdog не можуть гарантувати захист від примусової зупинки застосунку системою чи користувачем.

## MVP — перша версія

Першочергово реалізувати й перевірити:

1. Циклічні шаблони довільної довжини.
2. Генерацію графіка та ручні винятки на конкретні дні.
3. Місячний календар і головний екран із наступним підйомом.
4. Простий одноразовий будильник.
5. Планування, відтворення, відкладення та вимкнення локального сигналу.
6. Відновлення сигналів після перезавантаження та перерахунок після зміни часу.
7. Кнопку «Змінити сьогодні».
8. Контроль дозволів і зрозумілий індикатор готовності.
9. Локальне збереження розкладу та захист від дублікатів.

## Майбутні можливості

- Поступове збільшення гучності сигналу.
- Кілька незалежних сигналів для одного підйому.
- Вибір мелодії, вібрації та тривалості сигналу.
- Тест відтворення звуку й налаштування поведінки кнопок гучності.
- Експорт та імпорт шаблонів і винятків.
- Розширена діагностика сумісності з різними виробниками Android.

## Архітектура

Назви нижче описують логічні компоненти; вони не обов'язково мають бути окремими Gradle-модулями.

| Компонент | Відповідальність |
|---|---|
| ScheduleEngine | Генерація циклів, обробка винятків і розрахунок дат та часу |
| AlarmScheduler | Створення, оновлення та скасування системних сигналів |
| AlarmReceiver | Обробка події спрацювання |
| AlarmSoundService | Відтворення сигналу, вібрація, відкладення та вимкнення |
| CalendarUI | Календар, головний екран і редагування графіка |
| AlarmStatusMonitor | Перевірка дозволів, стану сигналів і відновлення після системних подій |
| LocalDatabase | Шаблони, графік, винятки, налаштування та історія |

## Критерії приймання

- Шаблон генерує правильні дати та час у межах обраного діапазону.
- Разовий виняток не змінює наступні дні циклу.
- Зміна або скасування дня синхронізується із системними сигналами без дублікатів.
- Простий будильник не змінює циклічний графік.
- Після перезавантаження застосунок відновлює майбутні сигнали, якщо Android дозволяє його запуск і необхідні дозволи надані.
- Якщо потрібний дозвіл відсутній, застосунок показує зрозуміле попередження.
- Минулі сигнали не захаращують список активних системних будильників, але історія зберігається в базі даних.

## Технологічний напрям

Попередній варіант реалізації: Kotlin, Jetpack Compose та Room. Остаточні технології й мінімальну версію Android потрібно зафіксувати перед початком реалізації.
